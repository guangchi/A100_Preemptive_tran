# 最新router、10ms窗口：GPU4/5四方案实验

2026-11-17。本轮重新运行baseline、只窗口排序、只抢占、排序＋抢占，均使用最新生产router：orjson直接解码、token数组编码一次复用于P/D、预先生成字节载荷、应用级keep-alive连接池。P=物理GPU4、D=物理GPU5，A100-SXM4-80GB，NV12/NUMA1，NIXL UCX CUDA路径，实际NVLink计数验证如下。

窗口10ms，C16、单槽、0.1ms poll；模型/2048 token预算/关闭prefix caching/保护参数沿用。15条固定请求含8 short（128 prompt tokens）、3 medium（1107）、4 long（10000），每条64输出token，逐token参考输出验证。客户端每批五条，共三批；25ms目标发送时刻[0,25,50]，50ms为[0,50,100]，窗口按实际P ASGI入口划分。

三轮，每轮每个方案全新启动P/D；方案顺序依次为[baseline,sort,preempt,both]、[sort,preempt,both,baseline]、[preempt,both,baseline,sort]，场景顺序25→50、50→25、25→50；每个正式场景前都完成相同负载预热。共24次正式与24次预热，360＋360条请求。开启pipeline trace和PD_API_TIMING，条件在本轮对照内一致。

## 本轮结果的解释

**25ms：** Short均值最低为排序＋抢占，相对baseline降低21.05%。只排序的Short发起→首次P调度为1222.70ms，baseline为1905.24ms，减少682.54ms；这是短请求在计算排队阶段获得收益的直接证据。组合的完整发送条件就绪→WRITE为5.28ms，只排序为58.75ms，表明优先级仲裁缩短了已可发送short的等待。但只抢占Short仍比baseline慢146.61ms：它没有窗内计算重排，且使用流式发布/event观察/writer路径，局部插队收益不足以抵消其他阶段的总差。上述阶段是软件观测，不是纯DMA耗时。

**50ms：** Short均值最低为排序＋抢占，相对baseline降低21.70%。只排序的Short发起→首次P调度为1181.15ms，baseline为1860.11ms，减少678.95ms；这是短请求在计算排队阶段获得收益的直接证据。组合的完整发送条件就绪→WRITE为4.83ms，只排序为57.19ms，表明优先级仲裁缩短了已可发送short的等待。但只抢占Short仍比baseline慢144.14ms：它没有窗内计算重排，且使用流式发布/event观察/writer路径，局部插队收益不足以抵消其他阶段的总差。上述阶段是软件观测，不是纯DMA耗时。

只排序与组合的六组同轮对照中，6/6组窗口成员和顺序完全一致。即使这些组相同，阶段耗时仍会随计算、输入时序和调度波动，因此不能把全部TTFT差严格归因给仲裁。

baseline的Short TTFT在50−25ms间变化-34.01ms，其中发起→首次P调度变化-45.13ms，其余调度后阶段合计变化+11.12ms。只排序的Short TTFT在50−25ms间变化-56.51ms，其中发起→首次P调度变化-41.54ms，其余调度后阶段合计变化-14.97ms。只抢占的Short TTFT在50−25ms间变化-36.48ms，其中发起→首次P调度变化-39.91ms，其余调度后阶段合计变化+3.42ms。排序＋抢占的Short TTFT在50−25ms间变化-43.39ms，其中发起→首次P调度变化-38.36ms，其余调度后阶段合计变化-5.04ms。

25/50ms是客户端批次发送间隔，10ms是P实际入口的收集窗口，两者不是同一个计时器。表中的共同原点检查量化了后两批更晚发起对TTFT的影响；若实际窗口成员相同，便不能用拆窗解释该对照的差异。剩余阶段变化包含计算排队、执行和完成观察，没有额外控制CPU调度或GPU时钟，不能将其唯一归结为25ms拥堵或NVLink速率变化。


## 验证与限制

全部720条正式/预热请求通过逐token、SSE、DONE、usage校验；36个正式排序窗口边界为10,000,000ns，稳定排序、收集截止后开始预处理、整窗注册先于首次调度通过。540条流式请求、6732对WRITE/DONE连续覆盖、单槽与最终通知通过；48次NVLink P Tx/D Rx均匹配每次5,817,499,648bytes KV payload，0.1%容差。实验期源码哈希未变，监控实验上下文仅GPU4/5，最终两卡已释放。运行前54项CPU检查通过。

三次重启/每组3次正式回放仅是描述统计，未给出显著性或普遍优劣保证。方案轮换不是完全随机化，trace与1ms API loop探针存在观察开销，未进行有/无采集配对。历史5ms/旧router/先前10ms只排序实验均非本轮同版本严格消融，保留旧数据但不混入本轮均值。
